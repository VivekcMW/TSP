# 🔐 CORE AUTHENTICATION PROMPT

## TheSocialPundit – Unified Login & Registration (PostgreSQL + Neon)

---

## 🎯 OBJECTIVE

Build a **single, frictionless authentication system** for **TheSocialPundit** using:

* **OAuth Providers**

  * Google
  * LinkedIn
  * Twitter/X
* **Email + Password**
* **PostgreSQL (Neon) as the production database**
* One-click login **automatically completes registration**

* One screen, one decision

  * Auditable

## 🗄️ DATABASE: POSTGRES (NEON)

### Core Tables (MANDATORY)

---

### 1️⃣ `users` — PRIMARY IDENTITY TABLE

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT UNIQUE NOT NULL,
  display_name TEXT,
  profile_image_url TEXT,
  onboarding_status TEXT DEFAULT 'pending',
  profile_source TEXT,
  role TEXT DEFAULT 'free',
  created_at TIMESTAMP DEFAULT now(),
  last_login_at TIMESTAMP
);
```

Purpose:

* One user = one identity
* Shared across all auth providers

---

### 2️⃣ `auth_providers` — OAUTH LINKING TABLE

```sql
CREATE TABLE auth_providers (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  provider TEXT NOT NULL, -- google | linkedin | twitter | email
  provider_user_id TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT now(),
  UNIQUE (provider, provider_user_id)
);
```

Purpose:

* Allow multiple providers per user
* Prevent duplicate accounts
* Enable account merging

---

### 3️⃣ `sessions` — OPTIONAL (IF NOT USING JWT ONLY)

```sql
CREATE TABLE sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  created_at TIMESTAMP DEFAULT now(),
  expires_at TIMESTAMP
);
```

---

### 4️⃣ `audit_logs` — SECURITY & COMPLIANCE

```sql
CREATE TABLE audit_logs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID,
  event TEXT,
  metadata JSONB,
  created_at TIMESTAMP DEFAULT now()
);
```

## 🔄 AUTH FLOW LOGIC (CORE)

---

### STEP 1: USER CLICKS PROVIDER

When user clicks:

* LinkedIn / Google / Twitter
* Redirect to OAuth provider
* Request **minimal scopes**:

  * Email
  * Name
  * Profile image
  * LinkedIn headline (optional)

---

### STEP 2: OAUTH CALLBACK

After OAuth success:

1. Extract:

   * Email
   * Provider user ID
   * Name
   * Profile image
2. Check:

   * Is this provider_user_id already linked?
   * Does a user exist with the same email?

---

### STEP 3: USER RESOLUTION LOGIC

#### CASE A: Provider already linked

* Fetch user
* Update `last_login_at`
* Log audit event
* Login success

#### CASE B: Email exists but provider not linked

* Link provider to existing user
* Prevent duplicate accounts
* Log merge event

#### CASE C: New user

* Create new user
* Create provider record
* Set:

  * `onboarding_status = pending`
  * `profile_source = provider`
* Log account creation

---

## 📩 EMAIL + PASSWORD FLOW

### Logic:

* Ask only:

  * Email
  * Password
* If email exists:

  * Validate password
  * Login
* If email does not exist:

  * Create user
  * Hash password (bcrypt/argon2)
  * Create provider record with `provider = email`

⚠️ Never store raw passwords
⚠️ Always hash + salt

## 🔁 POST-AUTH ROUTING

```text
IF onboarding_status = 'pending'
 → Redirect to onboarding start

ELSE
 → Redirect to inbox
```

---

## 🧭 ERROR HANDLING RULES

* OAuth failure → retry message
* Email already exists → auto-merge
* Provider conflict → resolve by email
* Never expose internal DB errors to user

---

## 🔐 SECURITY REQUIREMENTS (NON-NEGOTIABLE)

* OAuth tokens:

  * Used once
  * Never stored in DB
* Passwords:

  * Hashed
  * Salted
* Sessions:

  * Short-lived JWT or DB-backed
* All auth actions logged in `audit_logs`
